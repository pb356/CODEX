# 桌面归纳盒：UI 与交互优化需求

请基于当前 Windows 软件工程进行一次完整的界面与交互优化。本次只补充 UI 设计要求，沿用已确定的文件引用、安全、自动收件、固定框尺寸与滚动、动态壁纸等功能，不重复开发或改变文件处理方式。

## 1. 当前问题与设计目标

参考用户提供的两张现状截图：收纳筐是大面积直角色块，标题栏与内容割裂；设置窗口将颜色代码、数值范围和 0/1 开关直接呈现为密集输入框；空状态显示实现说明；图标、文字与留白缺少统一节奏。用户还反馈光晕生硬、不自然，需要重做效果。

目标是成熟、清爽、克制的 Windows 桌面工具：低对比表面、柔和边缘、清晰文字、自然反馈与少量必要操作。参考小智桌面的分区、主题和日常整理思路，不照搬其品牌、素材或界面。不要只在原参数表上加圆角和渐变，也不要为美化新增账号、广告、推荐内容或复杂导航。

## 2. 桌面收纳筐外形

1. 改为轻量的桌面分区，采用约 14 DIP 圆角、细微边缘和低强度阴影；不得出现厚边框、明显描边、巨大胶囊外壳或夸张玻璃反光。
2. 标题栏与内容区使用同一材质，避免当前浅标题带压在深色矩形上的割裂。仅用极轻的明暗变化或间距形成层次，不强行画粗分隔线。
3. 标题栏高约 40–44 DIP，左右内距 14–16 DIP。名称使用中等字重，项目数量降为次级文字，不再使用明显的“名称 (0)”工程式标题。
4. 右侧只保留折叠箭头与更多菜单。折叠采用有方向含义的箭头，不用容易被理解为最小化的减号。图标约 16 DIP，可点击区域不小于 28–32 DIP。
5. 常用入口清楚可见；次要按钮可在悬停或键盘聚焦时增强，但不能靠鼠标悬停才能发现核心操作。
6. 设置统一的首次创建默认尺寸，参考宽 340–380 DIP、高 280–360 DIP，并按屏幕可用区域约束；现有筐不因本次升级被强制重置尺寸。文件增减不能改变筐大小，溢出仍在框内滚动。
7. 折叠后是精致的同宽标题条，保留名称、数量与展开箭头。原内容区域实际消失，不残留透明遮挡；展开恢复布局与滚动位置。

## 3. 图标、文字与状态

1. 正式软件使用系统提供的实际文件和应用图标，不用任意彩色方块或通用图标替换所有类型。缩略图与系统图标采用受控的加载和缓存，不牺牲性能。
2. 默认图标约 40 DIP，提供小、适中、大三档。图标网格、文字基线和间距统一；内容边距约 12–16 DIP，项目间距约 8–12 DIP。
3. 文件名居中，最多两行，超长省略，悬停或键盘聚焦可查看完整名称；不能切掉文件名末尾而无法辨认，也不能让文字延伸到相邻项目。
4. 默认单击选择、双击打开，与 Windows 使用习惯一致。悬停使用淡填充，选中使用稳定的轻底色与边界，不能只依赖颜色区分，不能每经过一个图标就跳动缩放。
5. 字体使用合适的 Windows 中文字体与回退；参考名称 14 DIP、正文 13 DIP、辅助文字 12 DIP，正文与辅助文字保持足够对比，不以极细或极小字体制造“高级感”。
6. 空状态只保留小型图标和一句“拖入文件，开始整理”。“只保存引用、不移动原文件”等说明放在首次引导或帮助中，不常驻内容区。
7. 自动收件筐仅保留必要的“未分类/全部”视图和轻量新收件标记。没有新项目时不显示无意义的状态条，不堆积容量、路径、监听等内部信息。
8. 补齐空、正常、悬停、选中、拖入可接收、拖入不可接收、滚动、折叠、加载、文件失效等状态；失效入口给出重新定位或移除归类，不伪造文件存在。

## 4. 设置界面：从参数表改为可操作的产品界面

### 信息结构

每筐设置使用一个清晰的窗口或侧面面板，分为“外观”“特效”“布局”三个页面，默认进入外观；不再把所有参数同时排成表单。全局软件设置与单筐设置分开，避免用户误以为更改一个筐会改变所有筐。

外观首页只呈现最常用的四项：名称、主题、背景浓度、图标大小。其他设置收进“更多外观选项”。

### 控件替换

| 现有表现 | 新界面 |
| --- | --- |
| 背景/文字/光晕颜色要求输入 #RRGGBB | 主题预设、可视化色板与颜色选择器；高级 HEX 输入可选，不要求用户手写。 |
| 背景不透明度 16–245 | 用“背景浓度”滑块与 0–100% 的理解口径，内部做合法范围映射，不显示字节范围；背景变化不降低文字图标清晰度。 |
| 图标大小、字号纯数字输入 | 小/适中/大分段选项，确有必要的精调放高级选项。 |
| 0=关 / 1=开 | 有明确标签的开关，辅以一句必要解释；不显示布尔值。 |
| 0=自定义 / 1=轻柔 / 2=标准 | 有名称的选项或分段按钮，不让用户记忆数字编码。 |
| 光晕范围、亮度、星点数量全部常驻 | 默认仅选择关闭/柔光/星空及光感强度，其余参数采用合理预设或收进高级选项。 |
| 弹窗提示用户按数字范围填写 | 控件本身限制合法范围，输入错误就地提示，不用一串弹窗打断。 |

### 主题与预览

1. 提供“雾白”“松影”“烟蓝”三套完整主题：雾白为温润浅色，松影为自然灰绿深色，烟蓝为低饱和蓝灰。默认松影，与热植壁纸协调；所有主题均应保持清晰文字。
2. 统一设计令牌：颜色、字号、间距、圆角、边框、阴影、控件高度和状态。通过资源与样式复用，避免每个窗口各自硬编码。
3. 可参考的松影基准：主表面 #28372F，正文 #EDF2EE，次级文字 #A5B5AD，强调色 #B5CDBB；它们是设计起点，正式版仍需根据实际背景验证对比度。
4. 调整时实时预览当前筐，不改变真实文件。提供恢复默认、取消和完成。完成才提交该次外观设置，取消、Esc 或关闭时恢复进入前状态；不要出现关窗后意外保留半套设置的情况。
5. 显示项目数量等低频选项放进可折叠的高级区域。锁定位置等交互选项放布局页；整框穿透放其既定的安全入口，不误放在普通装饰选项旁边。
6. 适配目标 Windows 10 和 100%、125%、150%、200% 缩放；字号和窗口不能机械缩小。受屏幕高度限制时可滚动设置内容，关键操作按钮保持可达。

## 5. 自然的悬停光感

本节替代此前默认较明显的蓝紫光团与密集星点表现，不改变用户可关闭特效的选择。

1. 默认使用“柔光”：像鼠标附近有一小片柔和环境反射，而不是追着指针移动的明亮圆球。色调随主题，保持低饱和、低亮度，边缘没有可辨认的圆形轮廓。
2. 初始可采用约 90–140 DIP 的柔和影响范围、约 6%–12% 的轻微混合强度，以实际自然效果为准；限制亮度，不能照白整片背景或降低文件名对比。
3. 使用多个平缓过渡或柔和遮罩形成渐变，不能用硬边圆、明显放射纹、大光圈、固定亮环或高对比霓虹描边。
4. 指针移动后约 60–100ms 的平滑跟随感，移入约 150–200ms 淡入、移出约 250–350ms 淡出；移动停止后停止无意义的逐帧计算。不同帧率下速度应稳定，不能用无限堆积的定时器补间。
5. 星空是可选样式，默认极少量细点，参考当前可见区 3–6 个，大小和亮度有轻微差异，低频柔和出现消失；不沿指针喷射、不产生拖尾、不密集闪烁或随机跳位。不得为了星空增加全屏粒子层。
6. 光感与星点都处于文字和图标下方，限制在实际可见筐内；不参与鼠标命中，不因特效使按钮、拖放或滚动失效。
7. 折叠后仅作用于标题栏，隐藏、穿透、移出淡出后停止；尊重减少动画设置，提供关闭或静态光感。不为了装饰重新开启已暂停的动态壁纸。
8. 每一类过渡使用统一缓动，正常按钮不做弹跳或放大。应给出真实运行时的录屏，不以静态截图证明光晕自然。

## 6. 成熟交互的必要细节

- 标题栏拖动、双击折叠、重命名和点击更多菜单具有明确的命中区，不能互相误触。拖拽缩放时给出准确指针反馈。
- 更多菜单短而明确，按常用操作、外观、低频管理操作分组。删除收纳筐明确说明只移除归类，不能让装饰改版改变文件安全语义。
- 所有图标按钮有工具提示和可访问名称。支持 Tab 导航、可见焦点、Enter/Space 激活与 Esc 关闭；必要操作不能只有鼠标悬停入口。
- 拖入时仅当前目标筐轻微高亮，显示数量或简短反馈，不用覆盖全部内容的巨大提示层。正常动作轻反馈；需要处理的失败信息就地出现，批量失败可展开查看。
- 固定尺寸与大列表滚动沿用既有要求，滚动条在操作时清楚可见，新收件不使正在浏览的列表跳动。星空和光感不影响虚拟化、滚动和图标加载。
- 暗色与浅色主题都验证正常、悬停、选中、禁用和聚焦对比度；避免仅靠低透明白字叠加解决所有壁纸适配。
- 高质量材质可以渐进增强，但目标系统不支持或资源不足时，使用稳定的半透明或纯色低对比表面。不要把昂贵模糊当成精致界面的必要条件。

## 7. 实施与验收

1. 先检查现有原生工程的窗口、样式、资源和交互，列出需要替换的控件。重点重做收纳筐外形、设置页、状态体系与光感，不新增不相关功能。
2. 将交互示意落实回现有 Windows 软件；网页样例、UI 图片和演示数据仅用于沟通，不是原生软件交付，不得用网页替换真实文件管理行为。
3. 提供桌面正常状态、空筐、折叠、右键菜单、设置页、拖入、选中和失效文件的实际截图；补充光感、折叠和滚动的短录屏。
4. 用 1、20、200 个项目检查排版与空白节奏，并沿用大列表测试验证滚动；保持用户现有筐大小和文件引用，不擅自重置布局。
5. 在目标系统和不同缩放下检查文字清楚、控件对齐、窗口不过屏、焦点和命中区域正确；关闭特效与播放特效分别测资源，不能以美化导致明显性能回退。
6. 设置首页不得再出现 #RRGGBB 必填、16–245、0/1 开关或一整页开发参数；不再常驻“只保存引用”等实现说明；不能仅修改圆角就宣称已完成改版。
7. 如缺少原生工程或无法实机验证，明确交付的是设计规范与交互示意，列出未实施项，不虚构已打包或已通过测试。
