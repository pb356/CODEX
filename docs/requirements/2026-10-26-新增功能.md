# Codex 补充需求：热植动态壁纸与桌面自动收件筐

请在现有软件基础上增加以下两项功能。本文仅包含后续新增需求；此前已确定的普通收纳筐、折叠、外观、星空光晕、基础安全与安装交付要求继续沿用，不在这里重复，也不要求重新开发已有功能。

## 一、热带植物动态壁纸

### 1. 植物与视觉风格

- 第一版制作一套完整、写实的热带观叶植物场景，包含水晶花烛、其他观叶花烛、龟背竹、洞洞龟背竹、芭蕉等，组成自然舒展、有层次的群落。
- 保留真实叶形、比例、叶脉、裂孔和材质，体现花烛的绒面质感与芭蕉叶的舒展形态。避免塑料感、机械重复、卡通化和过度油亮，不用简化程序叶形替代写实素材。
- 使用植物自然的墨绿、灰绿、中绿与少量嫩绿，光线柔和，控制饱和度、高光和明暗反差，适合长时间办公。
- 提供明亮、柔和、偏暗三种色调，默认柔和；支持调整亮度、饱和度及柔和暗色遮罩，只影响壁纸，不影响图标和其他窗口。

### 2. 参考与正式素材

- 优先参考 Behance、Pinterest 上的写实热植摄影、植物装置及优质植物壁纸。检索方向包括 Anthurium crystallinum、Monstera、tropical foliage、botanical wallpaper。
- 先整理 6–10 张代表性参考图和作品页面链接供我确认，再制作静态构图，随后提供小段叶片运动预览。参考重点是植物形态、叶片质感、配色与组团方式，不直接照搬满屏密集布局。
- 正式素材采用原创、已授权或具有明确适用许可的高清资源，记录来源和许可；不能把网站截图作为正式壁纸，也不能将标注来源视作已获授权。
- 为动画准备独立植物或叶片图层、透明边缘、运动连接点及必要的遮挡补全，避免摆动时露出缺口、白边或重复纹理。素材随软件提供，运行时离线，不实时生成或下载。

### 3. 屏幕适配与可调构图

- 当前主要使用单个普通横向显示器，桌面图标与收纳筐主要集中在右侧。默认植物集中在左侧、左下和底部，向中部自然延伸，右侧约 40% 宽度保留为办公区。
- 留白通过柔和背景和植物疏密自然过渡形成，不使用生硬色块遮盖植物。留白核心区避免大叶片、高亮叶脉、密集纹理与明显运动；叶片摆动的完整范围也不能反复侵入该区。
- 疏密提供疏朗、适中、丰茂三档，默认适中。通过预设组团显隐和间距变化实现，保留自然植物尺度；丰茂模式也保留办公留白。
- 留白位置可选左侧、中部、右侧，宽度在屏幕宽度的 25%–55% 之间调节，默认右侧 40%。使用合理的预设布局，避免随机重排、重复堆叶或只缩放整张图。
- 第一版只调整整体疏密、留白位置和范围，不制作逐株植物拖动、更换和缩放编辑器。提供实时预览和恢复默认，保存设置并在重启后恢复同一构图。
- 自动读取实际分辨率和宽高比，验证 1080p、1440p、4K 横屏；等比例缩放并适当调整组团，不拉伸叶形、不露意外空边、不生硬截断主景。多屏跨屏编辑不纳入本次范围。
- 不读取或改动原生桌面图标位置，不自动移动收纳筐来迁就壁纸。

### 4. 轻柔随机的叶片运动

- 镜头与背景固定，部分前景、中景叶片轻摆，远景基本静止；不能用整张图片左右平移代替叶片动态。
- 叶柄连接点稳定，叶片围绕合理位置轻摆，叶尖和叶缘有少量柔和形变。初始参考摆幅约 1°–3°、周期约 6–14 秒，以自然、不干扰阅读的实效为准。
- 不同叶片的周期、幅度和延迟略有差异，保留协调的微风趋势；随机变化平滑，不能每帧随机跳角度，也不能所有叶片机械同步。
- 不出现整株漂浮、叶柄断裂、叶脉拉花、裂孔变形和边缘抖动。不加入鼠标视差、镜头运动、自动明暗变化、飞虫、落叶、闪光或声音。
- 支持动态开关与运动强度，暂停保持自然静态画面，恢复时平滑继续。

### 5. 桌面集成、暂停与验收

- 壁纸位于原生图标与收纳筐下方，不抢焦点、不拦截输入，不以置顶全屏窗口冒充桌面背景。先验证目标 Windows 10 的集成原型；依赖未公开 Shell 行为时披露兼容性限制，不满足核心约束时明确报告。
- 提供静态、节能和标准模式。标准模式上限 30fps，节能模式减少运动叶片及刷新率；尊重系统减少动画设置。
- 桌面被完全覆盖、锁屏、休眠、远程桌面或系统节能时暂停，停止持续渲染；重新可见后平滑恢复。不通过高频截图判断遮挡。
- 故障时降级静态，不影响收纳功能。记录原背景并提供恢复入口，关闭或卸载按设置恢复；用户期间主动换壁纸时，不反复改回或在退出时覆盖其新选择。
- 分别测试壁纸关闭、动态播放、与已有星空效果同时开启及暂停后的 CPU、GPU、内存和显存；不将基础空闲指标直接套用于动态播放。性能不足时先降级动画，保证桌面操作流畅。
- 验收确认：植物质感真实、右侧文字清楚、疏密和留白调整有效，分辨率切换无拉伸，暂停确实停止刷新，反复切换不积累任务或持续增加内存。

## 二、桌面自动收件筐与框内滚动

### 1. 自动接收保存到桌面的项目

- 新增一个专用“桌面收件箱”，名称可修改，外观与交互复用已有收纳筐，不重复建设基础功能。
- 在各软件选择真实桌面保存、另存为或导出，以及下载、复制或拖放文件到桌面后，自动在此筐显示，无需手动拖入。
- 自动收纳仅建立和维护引用：文件继续位于真实桌面路径，不移动、复制、重命名或改隐藏属性，不重定向桌面路径，不接管保存对话框。
- 不干扰连续保存、自动保存、相对路径关联及同目录素材。不能因文件暂时无占用或大小数秒不变，就推断文档已关闭并移动它。

### 2. 收件范围与分类行为

- 通过系统接口识别实际桌面，兼容 OneDrive 重定向，不硬编码路径。仅枚举顶层项目，不递归扫描项目目录；公共桌面中当前可见的普通文件和快捷方式只读纳入。
- 首次启用也纳入桌面已有的未分类项目，避免只收新文件而丢失旧入口。默认显示“未分类”，同时提供“全部桌面文件”视图，新项目带新收件标记。
- 拖入普通收纳筐仅改变分类：从未分类视图排除，真实路径不变；移除最后一个普通归类后返回未分类视图。同一路径不重复，覆盖保存与原路径替换更新原入口。
- 排除可识别的 desktop.ini、应用锁文件及下载中、保存中的临时文件，只过滤展示，不删除或移动。最终文件出现后纳入；不能将“条目已出现”表述为“保存已完成”。
- 正在写入或暂不可访问时适当标记更新中或暂不可打开，不强行读取内容和长期占用文件；用户主动打开时按系统与文件可用状态处理。
- 普通新增项目收到通知后约 1–2 秒内更新显示，不承诺这时已写入完成。监听事件合并、去重，启动和监听溢出后只做有界顶层补扫，不扫描全盘或高频轮询。
- 支持暂停、立即刷新和打开真实桌面；暂停或退出期间保存照常，下次启动或恢复时补入新增项目。

### 3. 保持桌面画面整洁

- 自动收件筐可独立使用，另提供明确可关闭的“桌面整洁模式”。首次开启前说明：暂时关闭 Windows 原生桌面图标显示，项目统一从收纳筐访问；文件仍在原桌面路径。目标是画面整洁，不是让真实桌面目录为空。
- 这是此前“不隐藏原生图标”规则的特定例外，仅在用户明确开启后生效；不得改文件 Hidden 属性、用遮罩盖住图标或擅自移动文件。
- 接管前记录原显示状态与恢复信息，确认所有桌面普通项目和已有分类有入口，回收站、此电脑等必要系统入口在托盘或系统入口区仍可访问，再关闭原生显示。任何步骤失败则回滚，不隐藏图标位置或排列变化等兼容性问题。
- 托盘始终提供“恢复原生桌面图标”和“打开真实桌面”。恢复不能依赖筐是否折叠、隐藏或穿透。
- 停用收件筐、关闭整洁模式、隐藏全部筐、正常退出或卸载前，恢复本程序接管的显示状态；重新显示筐后确认界面可用，再按用户偏好恢复整洁模式。
- 用户主动重新显示原生图标时停止接管，不反复隐藏，不覆盖其最新选择。故障后检查恢复记录并提供独立可用的恢复途径；不能保证强杀或断电时程序内清理一定执行。
- 使用说明保留手动恢复方法：桌面右键 → 查看 → 显示桌面图标。恢复及必要入口访问未通过测试时，不允许发布为已完成整洁模式。

### 4. 容量不受框尺寸限制

- 筐保持用户设定的宽高、位置和图标大小；项目增加不自动扩框、不缩小图标，也不因一屏已满拒绝添加。该滚动能力可复用于已有普通筐。
- 不设置固定每筐数量配额；实际规模受系统资源和配置存储影响，不承诺物理意义上的无限容量。
- 标题栏固定，内容采用随宽度排版的图标网格，超出部分垂直滚动。支持滚轮、触控板和可拖动滚动条，能访问第一项、最后一项和任意中间项目。
- 搜索与排序覆盖全部引用，不限当前可见项。拖拽靠近上下边缘时平滑滚动；仅筐内正常交互时消费滚轮，不能拦截框外或穿透模式的输入。
- 保留合理滚动位置，新增收件不强制跳回顶部；用户点击查看新收件时才跳转。内容减少后调整回有效范围，避免空白页。
- 使用可见项虚拟化、图标懒加载和有上限的缓存；只加载当前可见及少量预取项，不同时创建所有控件或读取所有文件内容。批量导入、搜索和排序不阻塞界面。

### 5. 新增功能验收

- 在办公软件和至少一种可获得的设计软件中测试保存、另存为、导出、连续保存及关联素材；同时验证浏览器下载、复制、临时名转最终名、同名覆盖、零字节合法文件和目录创建，原路径保持正常。
- 验证暂停期间新增、程序重启及监听溢出后补扫，无重复、无漏项；资源占用在批量事件结束后回落。
- 相同框尺寸下测试 10、200、1000、10000 个引用，验证首尾访问、持续滚动、搜索排序、分类及重启恢复。10000 项是测试点，不是容量上限；大列表性能单独报告。
- 验证整洁模式首次接管、停用、隐藏全部筐、穿透、手动恢复、Explorer 重启、崩溃、强制结束及卸载，不移动文件、不遗失访问入口。无法验证的项目明确标记，不声称所有软件与所有故障情形均已覆盖。
